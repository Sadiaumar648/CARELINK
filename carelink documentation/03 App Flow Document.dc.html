CareLink App Flow Document

Every screen, every navigation path and what happens when each button is pressed — for the parent, the caregiver and the agency administrator.

1 · Navigation model

The application has one public shell and three private shells, chosen by the signed-in account's role. A user never sees navigation belonging to another role, and there is no shared dashboard.

ShellPrimary navigationPattern
PublicHome, How it works, Sign in, RegisterTop bar; single-column marketing pages
ParentSearch, Bookings, Children, Messages, AccountBottom tab bar on mobile, left rail on desktop; five destinations, no more
CaregiverRequests, Schedule, Profile, Messages, EarningsSame pattern, larger targets, icon and word on every tab
AdministratorOverview, Roster, Verifications, Bookings, Reports, SettingsPersistent left sidebar, desktop-first, dense tables

Three rules hold everywhere. A destructive or committing action always asks for confirmation and states what it commits to. Every list has an empty state that says what to do next, never a blank panel. And every screen a caregiver uses carries a read-aloud control and voice input on its text fields.

2 · Entry and onboarding

2.1 First contact

The landing page states what the agency is, that its staff are verified, and offers two doors: Find a caregiver and I work with the agency. The second door exists because most caregivers arrive already on the roster, holding an invitation rather than choosing to sign up.

2.2 Parent onboarding — four steps

  1. Account. Name, phone, email, password. Create account writes the account with the parent role and signs the user in. A duplicate email returns to the field with an inline message, never a lost form.
  2. Household. Area, address, household notes, emergency contact name and phone. Continue saves; Skip for now is offered but the parent is told booking requires it.
  3. Verify. ID type and number, a photograph of the document, one reference, and the optional live selfie. Submit for review moves status to pending review and returns to the dashboard with a banner explaining the wait. Browsing is available immediately; requesting a booking is not.
  4. First child. An invitation to build the Ward Care Profile, framed as the thing that means never explaining a routine twice. Skippable, and re-offered on the first booking attempt.

The parent lands on Search with a progress strip showing which of these four remain.

2.3 Caregiver onboarding — invitation first

The administrator has already created the roster record. The caregiver receives an invitation code, enters it with their phone number, and sets a password — claiming the existing record rather than creating a second one. From the first screen, a prominent speaker control reads each instruction aloud, and every text field offers a microphone alternative.

  1. Claim. Invitation code and phone; set a password. Wrong code returns an inline message and an offer to call the agency.
  2. Profile. Photograph, spoken or typed bio, years of experience, hourly rate, service areas, skill tags chosen as large labelled cards rather than a checkbox list, and languages spoken.
  3. Availability. A weekly grid of days against morning, afternoon, evening and overnight, tapped rather than typed, plus specific dates marked unavailable.
  4. Verify. The same submission as the parent, with each field spoken aloud on focus, and photograph capture guided by a live outline and a spoken instruction. Certifications are an optional extra upload.
  5. Done. A confirmation that the agency is reviewing, with an explanation that requests arrive once approved. The caregiver lands on Requests with a pending-verification banner.

3 · The parent journey

3.1 Search

The screen opens on one field: Describe who you need. Beneath it, Or use filters expands area, date, start and end time, budget, minimum experience, minimum rating and skill tags. Both routes end in the same query.

ActionWhat happens
Search on the plain-language fieldThe sentence goes to the language model; the interpreted filters return as editable chips — "East Legon · Sat 6 Sep · 14:00–18:00 · newborn care · ≤ GH₵30/hr" — with a note that they can be corrected. Confirming runs the search. A parsing failure opens the filter panel pre-filled with whatever was understood, with a plain explanation
Microphone on the plain-language fieldSpeech-to-text fills the field; the transcript is shown for confirmation before the search runs
Apply filtersRuns the hard filter, then ranks the survivors; results replace the panel and the applied filters stay visible as removable chips
No resultsNames the constraint that eliminated the most candidates — usually the time window — and offers to relax it, rather than showing an empty list

Each result card carries the photograph, name, verified badge, rating and review count, years of experience, hourly rate, service areas, up to four skill tags, and a match score. Tapping the score expands the breakdown — availability, area, skills, rating and experience, budget — each with its contribution. Tapping the card opens the profile.

3.2 Caregiver profile and booking request

The profile shows the full bio, verification status and what was verified, certifications, all skill tags, availability for the next fortnight, and reviews with dates. Request booking opens a four-step sheet.

  1. When. Date, start and end time, pre-filled from the search. Hours and total recalculate live at the caregiver's rate. Times outside declared availability are refused at the field with the reason.
  2. Who. Which child, selected from the Ward Care Profiles. A parent with none is offered a short create step here.
  3. Where and notes. Address, defaulted from the household, plus one-off notes for this booking only.
  4. Review. The full terms, a statement that the caregiver will see the selected child's care profile, and the emergency contact being shared. Send request writes the booking as pending.

An unverified parent reaching Send request is stopped with an explanation and a link to finish verification — the check happens before the sheet opens, not after the form is filled.

3.3 Booking detail — the screen that changes with state

One screen, five faces. The header always shows caregiver, date, hours and status; the action area is what changes.

3.4 Payment

Pay with Mobile Money opens a three-step sheet: choose network (MTN, Telecel, AirtelTigo); confirm the number, defaulted to the account phone; confirm the amount with the breakdown of hours at rate. Confirm payment shows a waiting state with a spoken and written instruction to approve the prompt on the phone. Success shows the reference and moves the booking to paid. Failure states the reason and offers a retry; the booking stays accepted and payable. A timeout keeps the payment recoverable and tells the parent to check before retrying, so nothing is paid twice.

3.5 Children, messages, account

Children lists each Ward Care Profile with its last-edited date; opening one reveals sections for allergies and medications, meals, routine, special needs and house rules, each editable in place. A note states that changes are visible to caregivers on active and future bookings. Messages lists booking-scoped threads, newest first, with unread counts; a thread closes when its booking closes and remains readable. Account holds the household profile, verification status with a resubmission route if rejected, and the reports the parent has filed with their resolution status.

4 · The caregiver journey

4.1 Requests

The landing screen is the inbox of work. Each request card shows the parent's first name and verified badge, date and time, hours, area, the child's age, the total the caregiver will be paid, and how long the request has been waiting. A speaker control reads the whole card aloud.

Opening a request shows the full terms, the parent's Ward Care Profile for the named child — allergies, medications, meals, routine, special needs — and the one-off notes. Accept asks for confirmation, states that the terms lock, checks for an overlap against accepted bookings and refuses with the conflicting booking named if one exists. Decline asks for a reason from a short list plus a free field; the request closes and the parent is told without the reason being framed as a judgment.

4.2 Schedule and session

Schedule is a list by day — today first — of accepted and paid bookings, each showing time, area, child and payment status. On the day, Start session confirms, moves the booking to active and reveals the parent's emergency contact for the duration. During a session the screen holds three things only: the care profile, the message thread, and End session. Ending it confirms, moves the booking to completed, and shows what has been earned. Report a problem is present throughout.

4.3 Profile and earnings

Profile holds photograph, bio, rate, skills, service areas, certifications and the availability grid, each editable, with a standing note that changes never alter an accepted booking. Verification status is shown plainly with what remains outstanding. Earnings lists completed bookings with amount, date and payment reference, and totals for the week and the month — the caregiver's own record, which they have never had.

The verification review screen carries a standing line: the photo result is a plausibility aid, not a certified match, and the decision is the reviewer's. The administrator's decision is stored separately from the model's verdict, which is what makes the comparison in the evaluation plan possible.
